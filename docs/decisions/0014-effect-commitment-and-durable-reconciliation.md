# ADR 0014: Bind the expected effect before dispatch and preserve receipt state

Status: accepted for the Promisory adapter; the existing unbound live claim remains unresolved.

The approved 18 → 19 November recovery test now has a matching native Jira read and exact operation-tagged history entry. Its original Decionis grant nevertheless cannot complete the supported reconciliation path. The authenticated dossier and a bounded read-only inspection of the exact claim show Protocol 1.1 with no `expected_effect_digest`. The deployed authority requires that pre-dispatch commitment for confirmed effect evidence and rejects older evidence formats for a Protocol 1.1 grant. The initial reconciliation request also omitted required `effect_evidence`. The SDK 0.5.0 `LocalAuthority` test double permits that omission, so its successful synthetic reconciliation did not exercise the deployed contract. [Live evidence](../evidence/2026-11-11-recovery-test/authority-claim-state.json).

Promisory now computes `promisory.jira-date-effect.v1` before asking for a grant. It hashes only trusted installation/cloud/principal context, the stable issue ID, operation ID, stable `duedate` field, and independently prepared before/after dates. No Teamwork Graph data or derivative participates. The SDK binds `expectedEffectDigest` into the intent and requires the returned claim to match it.

Recovery constructs the versioned observation only after fresh current-user Jira access establishes the current date and native operation receipt. It matches the observation to the sealed intent and the claim's existing effect commitment before sending Protocol 1.1 effect evidence. The observer ID comes from host configuration and must equal the authority key identity already trusted by Decionis. The observation includes a digest of the closed, permitted REST/intent projection, time, method and claim correlation. The authority continues to verify the grant, claim, correlation, observer, original commitment and causal times. Missing or changed bindings fail closed; the adapter never invents a commitment after dispatch or falls back to a weaker format.

Receipt acceptance and recovered completion are distinct. A failed reconciliation preserves an already recorded INDETERMINATE receipt in the encrypted vault. If a receipt acknowledgement was lost, only a positive response from the supported reconciliation resource can settle it; a receipt replay refusal never counts as acceptance. Responses are bounded and require `reconciled: true`, `resolution: FINALIZED`, a reconciliation ID, evidence hash and delivery status. An accepted durable outbox record is distinguished from completed Decision Chain delivery in the typed diagnostic. The caller's result is retained if telemetry fails.

Nine independent contract/recovery tests cover the mandatory evidence shape, scope/date binding, absent commitments, forbidden extra provenance, malformed or refused responses, pending delivery and process-restart retries. The full suite now passes 139 tests in 20 files. No Decionis source, policy semantics, signing material or shared production deployment changes are part of this fix.

The original grant remains INDETERMINATE and its native Jira effect remains verified. Existing signed artifacts, the sealed claim, retained disk and one-use fault marker must be preserved. A fresh result check cannot repair an omitted original commitment. [Operator review](../authority/recovery-operator-review.md) records the exact case and remaining acceptance gate. Full lost-response recovery is not claimed.
