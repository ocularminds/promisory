# ADR 0010 · Exact DCI policy values and an isolated test executor

11 November 2026. Policy repair and test deployment authorized and applied; execution verification remains held.

The user approved the KAN-2 due-date change from 12 to 18 November in the dedicated Promisory installation, expiring 12 November 2026 at 00:00 UTC. A live SHADOW check of approved revision v2 allowed a different date. Decionis policy-core's `values_equal` parses numeric prefixes before text: both ISO dates become 2026; different principal IDs with the same numeric prefix also compare equal. The real WASM module reproduced date, principal and issue-prefix failures locally.

Use escaped, anchored `MATCHES` predicates for the approved opaque string values. Retain the same business effect, required evidence, checker and expiry. The technical correction is immutable revision v3, `457e04a4-0a1d-4f18-8bca-7a9a5df2adc8`; pin this UUID in deployment configuration. Do not rely on an opaque identifier's `EQ` comparison or silently inherit a newer named revision. UI/model inputs still cannot choose policy, tenant, principal or mode.

The faulty v2 artifact is retained as HISTORICAL. A one-revision administrative rollback verified its organization, revision and canonical payload SHA before using the existing monotonic lifecycle transition. Native API read-back and an explicit old-UUID evaluation after v3 activation confirm containment. No grant, claim or Jira write occurred in these probes. The 18 v3 live cases verify ALLOW, BLOCK and missing-evidence ESCALATE with the expected policy/version and no execution credentials. Failure and repair evidence remains in [the live ledger](../evidence/2026-11-10-live-test-site/README.md).

The user directed deployment discovery to SwarmPay/Decionis. Their application pattern is suitable: `decionis-aks`, namespace `decionis`, ACR `decionisacr.azurecr.io`, class `decionis-nginx`, retained `decionis-zrs` storage. Namespaced access now works. Do not trigger their broad production pipeline or include either dirty checkout in this release.

Use a separate `promisory-test-executor`: one replica, Recreate updates, non-root read-only filesystem, no Kubernetes service-account token and a private persistent journal/claim volume. Only the ingress controller may reach HTTP; outbound traffic is DNS, public HTTPS excluding private/link-local ranges, and HTTPS to that exact ingress controller. The final rule was required by a live failure: the API's public load-balancer address is translated to the controller's private pod address inside AKS. Application code separately fixes Decionis, Atlassian API and Forge-key destinations. The health probe returns process liveness, not authorization or readiness to execute.

The minimal build context contains the remote and its three shared source packages plus dependency manifests/lockfile. It excludes credentials, evidence, product documents, fixture source and Git state. Node is pinned by official image digest. ACR run `cj47`, registry metadata, nine checks in the exact Linux image, trusted HTTPS and state across pod replacement have now passed. The actual deployed FIT/OAuth path still requires verification.

The user approved the 4 GiB Premium_ZRS disk/test hostname and the separate shared observer rollout; both are applied. The API image was preserved. Initial deployment used SHADOW with sharing and verification false. On the later instruction to turn on enforcement, mode changed to ENFORCEMENT and narrow intent/REST sharing was enabled, with verification still false. Three live authority denial cases passed, but they used synthetic inputs and an inert handler. Preserve the hold until the real Forge invocation is verified. ALLOW, a signed dossier, a matching final date or an enabled flag never substitutes for grant/claim/finalization and trusted reconciliation.
