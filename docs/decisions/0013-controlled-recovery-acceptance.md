# ADR 0013 · Isolate the live recovery acceptance probe

11 November 2026 · approved and running; exact native history reconciliation pending

The [normal governed Jira effect](../evidence/2026-11-11-governed-write/README.md) passed grant, claim, write, read-back and finalization. It does not exercise durable recovery after an uncertain send. The original accepted policy covers only 12 → 18 November and cannot authorize a second date effect. The [separate recovery plan](../authority/recovery-test-plan.md) proposes 18 → 19 November for the same issue, account and installation, with the same expiry and a new human checker decision.

Use an operator-only Node preload in an immutable ConfigMap on the existing test executor. Keep it outside application imports, manifests and normal image packaging. No fault-control field or endpoint is exposed to the UI, Rovo or ordinary requests. The actual executor image, FIT/hosted authentication, source checks, independent review, policy selection, supported grant/claim and native write implementation are preserved.

The preload narrows Jira PUT transport to the exact test target/payload, reserves an exclusive private marker on the existing durable volume, and forwards the original request at most once for the whole plan. After a real native success response, it persists a closed success-observation record and throws before the executor can observe that acknowledgement. A subsequent retry, a competing operation or a restarted process cannot forward another test write. Reads and authority transport remain unchanged. Absent exact configuration, expired scope or unavailable durable reservation fails closed. The marker carries no bearer token, request body, provider error text or Graph data.

The native acknowledgement is test instrumentation, not reconciliation proof. Acceptance still requires the production executor to remain uncertain, survive a process replacement, receive fresh OAuth from the original principal, identify the exact native history effect and complete Decionis reconciliation/finalization without another write. Evidence must label the fault as deliberately injected and distinguish synthetic transport tests from live observations. An unrecognized history representation stays uncertain until independently established.

The preparation tool performs read-only identity/runtime/state checks and server dry runs for narrowly guarded resources. Activation follows the new human approval. Cleanup restores the prior policy and normal image command, removes only the test additions, and retains operation evidence and the one-use marker. No shared production service, paid resource, credential scope or Forge permission changes. An unresolved operation must remain recoverable during cleanup; changing policy or deleting claims cannot stand in for reconciliation.

Six synthetic transport tests cover successful acknowledgement loss, concurrent/restart exclusion, exact-write narrowing with read pass-through, real refusal/uncertainty, unavailable state and expiry, and exact environment requirements. They passed within the original 122-test suite. The approved live run has now observed native 204, deliberate acknowledgement loss, durable restart and a matching current date. Exact native history matching remains open; the probe marker cannot substitute for it.

A temporary second preload diagnoses the existing receipt lookup without changing its outcome. It watches only bounded GET changelog responses for the fixed cloud/issue and operation, leaves the original response intact and makes no additional request. A strict versioned projection retains HTTP/page metadata, operation-tag matches, due-date field identity and format categories; only the approved two calendar dates can be retained. It excludes provider prose, arbitrary change values and credentials. Per-page private files prevent a later page from replacing an earlier match. Three contract tests cover projection boundaries, unchanged request/response behavior, page separation and refusal/pass-through. Its separate immutable ConfigMap and mount are removed with the original probe after reconciliation; no authority or parser behavior is supplied by this diagnostic. [Current evidence](../evidence/2026-11-11-recovery-test/README.md).

The live walkthrough also exposed ambiguous status copy. RECONCILING is a saved state requiring a fresh user check, so its label becomes **Result unresolved** rather than implying an active background request. A recorded uncertain finalization is described separately from verified completion; its raw enum moves under exact evidence. The reviewed before-date is labelled as reviewed rather than current after execution. Result checking mirrors the existing server rule that only the original acting account can obtain the required fresh authorized invocation. These presentation changes do not change operation or authority semantics.

The native observation then established the parser mismatch: one exact tagged `duedate` entry has raw ISO dates in `from`/`to`, while `fromString`/`toString` contain presentation values. The adapter now requires that exact tag, stable field ID and validated raw calendar dates. It accepts an explicitly null prior value when the reviewed effect expects null, but never equates a missing value with null or falls back to display text. Invalid/unrelated entries cannot confer proof; HTTP denial, invalid pages and the existing five-page bound remain unresolved. Five synthetic adapter tests and the full 130-test suite pass. The existing test service received a narrowly reviewed image update for this correction, preserving the policy, original probe, history observer, claim and volume. Fresh native reconciliation remains necessary after deployment. [Observed history and deployed correction](../evidence/2026-11-11-recovery-test/README.md#observed-parser-mismatch-and-deployed-fix).
