# ADR 0012 · Bind the hosted Forge caller independently of missing FIT module data

11 November 2026.

The installed 3.2.0 connection check reached the executor and passed FIT signature, app, environment, installation and cloud checks. It failed the module comparison. The [sanitized observation](../evidence/2026-11-11-connection-diagnostics/installed-connection-user-check.json) reports an unrecognized module category; it does not establish the exact omitted or populated value. Atlassian acknowledges missing FIT module information on hosted-function calls in [FRGE-1933](https://ecosystem.atlassian.net/browse/FRGE-1933), linked from its [developer support response](https://community.developer.atlassian.com/t/why-does-a-forge-web-triggers-calling-invokeremote-produce-a-fit-with-empty-strings/95916). The documented [AppContext API](https://developer.atlassian.com/platform/forge/runtime-reference/app-context-api/) supplies the module key, app version and invocation ID inside the hosted function.

Require a runtime-validated `promisory.hosted-invocation.v1` attestation on every remote route. Forge obtains all three fields directly from `getAppContext()`, checks its app/environment/installation against the trusted request context, and signs the attestation together with the exact POST method, fixed path and request body under `promisory.authenticated-request.v2`. The header is `x-promisory-origin`; its strict schema allows only the server's Jira UI module keys and their single resolver. There is no caller/model override. Rovo, triggers, Confluence-only surfaces and arbitrary modules cannot become execution sources.

The remote still verifies the FIT signature, issuer, audience, expiry and required claims, exact installation/environment/cloud/app, native principal, and fixed Jira API destination. A nonempty FIT module must be allowlisted and must equal the HMAC-authenticated hosted module. An empty FIT module is never treated as verified: the hosted attestation is required, including a version that matches the FIT. Every route authenticates the new method/path/origin/body signature before any Jira access or authority call. Old body-only signatures, absent attestations, changed paths, changed identities and conflicting versions/modules fail closed. The existing HMAC key is preserved.

The connection result advances to `promisory.remote-connection.v2`. It reports `fitModuleKey: null` and `moduleVerification: HOSTED_CONTEXT` when FIT module data is absent; otherwise it reports the exact matching FIT/hosted module with `FIT_AND_HOSTED_CONTEXT`. Forge verifies the returned hosted module/version against its own current runtime attestation. The collector accepts only fresh, strict results for the deployed version, primary test account and pinned installation. This distinction avoids claiming that Atlassian supplied a module value when it did not.

The attestation adds only explicitly enumerated trusted runtime metadata. No source work, profile content, Graph data/derivative, OAuth, HMAC value or grant is logged. Method/path binding also prevents moving an authenticated request between remote routes. Existing proposal review, source revalidation, exact Decionis policy, execution grant/claim, reconciliation and fulfillment remain separate. The verification hold remains active through the paired backend/Forge rollout. The source allowlist names the existing Jira UI entry points and their resolver. No policy, resource, tenant/user binding or Forge permission scope changes.

Local tests cover absent and conflicting attestations, the missing-FIT-module case, cross-route/modified-origin/legacy-signature refusal, fully signed forbidden sources, runtime version/context checks, explicit proof provenance and Rovo refusal. Live validation must still establish what this installed call supplies. [Evidence](../evidence/2026-11-11-hosted-invocation/README.md).

The subsequent 3.3.0 live check establishes that both FIT and hosted context name `promisory-workspace`. The resolver-only expectation was the observed defect. This live check used `FIT_AND_HOSTED_CONTEXT`; the documented absent-module branch has local synthetic coverage, not a claimed live observation. Matching current-user OAuth also passed. The exact test enforcement hold was then released under the existing user authorization.
